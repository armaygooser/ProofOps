# 演示真实性边界

ProofOps 当前版本用于证明 CyberGuard 治理模式可以迁移到工业运维。它是可运行的确定性演示，不是生产工业控制系统。

## 哪些是真实执行的

| 能力 | 当前实现 |
|---|---|
| API 与状态机 | FastAPI 真实运行并强制阶段转换，非法顺序返回 409 |
| 证据摘要 | 对每份演示内容实时计算内容 SHA-256 与封装 SHA-256 |
| 操作审计链 | 对提案、批准、执行、回滚实时计算前序哈希、记录哈希与 HMAC-SHA256 |
| 审批绑定 | 批准必须携带当前提案的完整 64 位哈希；错误哈希会被拒绝 |
| 审批有效期 | 执行前检查批准记录与提案绑定以及 15 分钟过期时间 |
| 动作允许列表 | 只接受 `activate_backup_cooling / B2-CHILLER-02` |
| 回滚语义 | 回滚必须绑定执行记录哈希，并使此前复测结论失效 |
| 容器运行 | 前后端 Docker 镜像、反向代理和健康检查均可实际启动 |

## 哪些是确定性模拟

| 能力 | 当前实现与限制 |
|---|---|
| 工业遥测 | 温度、功率、心跳和设备状态来自固定 B2 场景，不来自真实 BMS/PLC |
| 七个 Agent | 角色、顺序和调查结论由后端预设，没有实时调用模型或 AgentTeams Worker |
| 权限隔离 | 权限标签和流程边界存在，但七个角色不是独立进程或独立凭据主体 |
| Evidence 内容 | 哈希计算真实，输入内容是场景 fixture，不是外部工具回执 |
| 设备执行 | `BMS.START/BMS.STOP` 修改数字孪生状态，回执固定为 `accepted` |
| 独立复测 | 复测阶段与执行阶段分离，但仍在同一进程中，读取确定性孪生状态 |
| 人类身份 | 审批状态门真实，但审批人是输入字符串，没有 OIDC、签名或审批密钥鉴权 |
| 持久性 | 审计链保存在进程内存中，重置或容器重启会创建新链 |
| AgentTeams | Worker/Skill 是部署草案，尚未在实际 Controller 留下运行回执 |
| Element Web | 已提供从房间链接打开 Service Publishing URL 的路径，尚无实际发布 URL |

## CyberGuard 复用的准确说法

ProofOps 没有在运行时连接 CyberGuard 服务，也没有把 CyberGuard 作为包导入。`backend/proofops_api/governance.py` 根据 CyberGuard v0.14 `response-executor` 的治理契约和实现方式编写了本地工业适配器，包括规范化记录、SHA-256、HMAC 串联、提案审批绑定、审批过期和回滚关闭。

因此当前版本可以准确表述为：

> 基于 CyberGuard 治理契约实现的跨领域适配原型，证明相同治理模式可在工业数字孪生场景运行。

不应表述为：

> 已接入 CyberGuard 在线服务、已连接真实工业设备、已完成真实 AgentTeams 多智能体运行。
